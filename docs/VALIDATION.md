# 验收清单与证据边界

当前产品为 1.1.0 预览。自动测试、打包成功、已有旧版实机记录分别提供不同证据，不能互相替代。下表是每次交付的检查要求；“待记录”不是通过结论。最终实测结果应在交付验收报告列出时间、系统、Cursor 版本、commit、产物哈希与命令/截图依据。

| 范围 | 检查要求 |
| --- | --- |
| 公开源码 | 干净源码解压可安装依赖、同步固定上游、构建；公开来源记录可提交；无私人状态 |
| 安装恢复 | 正常安装、重复安装、写入中断、已损坏或缺失备份、记录写入失败；失败退出与保留恢复信息 |
| 版本保护 | 未支持平台/版本拒绝；当前 commit 不接受其他版本备份 |
| 技术内容 | 变量、占位符、路径、快捷键、命令和代码不被翻译改变 |
| 动态正文 | 纯英文、中英混排、长段落、流式变化、文本节点复用、原文切换 |
| 性能 | 长会话的无关节点变动不会扫描整个历史；需区分模拟 DOM 与实际窗口耗时 |
| 实际 UI | 重启、编辑菜单、右键、设置、Agent、历史标题与正文；逐页记录漏译 |
| 离线连接 | 首次配对、实际 Electron 来源请求、暂停、重连、重启与失败恢复 |
| 分发 | VSIX 与 config 版本一致；source/full ZIP 文件与许可齐全；内外哈希匹配 |
| 新用户 | 无系统 Python/Node、中文与空格路径、多安装目录、权限不足 |
| GitHub | 实际远端 CI、预发布资产下载校验；本地生成 YAML 不算执行完成 |

## 当前记录的使用

1.0.8 的 [历史修复记录](REPAIR-1.0.8.md) 只证明当时记录的环境和行为。1.1.0 修改后须重验受影响项；不得自动继承“全部通过”。

截至本次本地源码交付，远端 GitHub CI 和新 Windows 用户独立验收尚未完成；实际桌面测试以另外的交付报告为准。工作流未执行过就保留“未验证”。

## 建议的验收材料

- 配置版本、Cursor 完整版本和 commit、系统架构。
- 测试命令与退出结果，失败用例的原始与恢复后哈希。
- 公开构造的语言样例及原文切换结果；勿附用户真实聊天内容。
- 首次安装、重启、回滚的实际界面结果；截图需脱敏。
- 所有交付文件的 SHA-256、完整性清单验证和干净源码构建结果。
- 未解决问题、尚未测环境和支持边界。

在全部必需的实际场景通过前，保持预览发布状态，不承诺全版本、全系统或任意正文达到人工汉化水平。
